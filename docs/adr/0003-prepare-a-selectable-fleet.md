# Prepare and validate a selectable fleet

Add two cars from each of the six source games, keeping the original 350Z GLB and receipt unchanged. A generated roster shares each car's identity, wheel coordinates/radii, body dimensions and prepared asset path between rendering and vehicle dynamics. Brackets and gamepad bumpers cycle the fleet, replace the model and collider together, and recover the car stopped on a nearby road. Each car uses the same arcade force/mass tuning; these are not reconstructed native performance specifications.

Static exporters disagree about scenes, axes and wheel ownership. Prepare the selected default scene offline, retain source vertex/index/normal/UV/colour and embedded image bytes, and place its meshes under a body root or four explicit animated wheel pivots. Store the source hash, normalization and mesh/node correspondence in a receipt. Native source wheel names/attachments define ownership; spatial quadrants define the common front/rear and left/right order after orientation normalization. Source driver helmets are omitted. Redline add-ons remain visibly labelled as add-ons.

Compare the final fleet against the unchanged 350Z with the same physics contract and matched front/side/rear captures, plus a native acceleration/turn/handbrake/braking/reset sequence. Structural validation is distinct from visual review: loading nodes cannot prove visible quality, and blank captures must fail. When a locked desktop cannot provide a drawable window, the same Bevy camera, lighting, materials, HUD and models can render to an explicit GPU image target; report that mode instead of representing its measurements as window performance.

Preserve the source-era art and disclose detail differences: GT1 source meshes are substantially simpler than GT4. Fidelity checks concern faithful model/texture retention, complete assembled parts, correct pose/materials, clean rendering and feature parity. They do not claim that a PS1 mesh has GT4 geometric detail or that GRID reproduces the games' original shaders.

Shared cabin/lamp materials require narrower scope. MC3 named lamp parts receive independent material copies. The GT500's selected body UV blend surfaces are partitioned using their measured height gap: cabin triangle centroids are at least 0.485 m high, while front-lens centroids are at most 0.184 m. The 0.30 m threshold preserves the complete rear window as one cabin material; a length bound would split that connected surface. Only supplementary index buffers are appended. The original binary payload remains intact, every source attribute/image is unchanged, and an independent oriented-triangle multiset check proves that no source triangle was lost, duplicated or changed by the partition. This material grouping is a preview choice, not recovered native part ownership.

Visual inspection rejected the initially considered Corvette because its source wheel faces were plain caps. The selected Redline 911 has complete textured Fuchs rims. MC3 wheel inner plates follow their explicit native black-matte role, keeping spoke openings legible. MCLA rear lamp covers use translucent red separately from reflector/backing materials, exposing preserved source lamp geometry.

The selected 911 has a dedicated cabin glass material, so its dark cabin preview needs no triangle partition and leaves separate lamps unchanged. It follows the 350Z cabin treatment while retaining the source texture and interior geometry.

A straight rear chase-camera check exposed a split GT500 rear window missed by the oblique comparison views. A regression independently recovers its 26-triangle position-connected source surface and requires every triangle to use the cabin material. It failed before the height-gap correction and passes afterwards.
